## 0. 文档定位

本文件不是"缠论学习笔记"，而是将缠论相关定义转换成**可程序化、可回测、可审计**的工程规格。

必须严格区分三类内容：

1.  **原典规则**：缠论原文已有明确描述的定义或操作逻辑。
2.  **工程实现规则**：为了让计算机能够执行，对原典进行数据结构、状态管理、确认时点等方面的工程化表达。
3.  **实验参数**：需要通过历史数据和模拟盘验证，不能冒充缠论原理。

> 核心原则：如果原典没有规定，程序不得把一个工程假设包装成"缠论定理"。

# 1. 系统目标

## 1.1 核心目标

构建一个只使用1分钟K线为核心行情输入的缠论 Trading Agent：

``` text
1分钟K线
    ↓
包含关系处理
    ↓
分型
    ↓
笔
    ↓
线段
    ↓
中枢
    ↓
1分钟走势类型
    ↓
同级别分解
    ↓
A0 → A1 → ... → An
    ↓
盘整背驰 / 不创新高新低 / 第39课状态机
    ↓
当前交易状态
    ↓
BUY / SELL / HOLD
    ↓
落到已确认分型对应的K线
    ↓
结构止损
```

## 1.2 不做的事情

v1.0明确不引入：

-   5分钟/15分钟/30分钟等高级别信号作为交易依据
-   一买、二买、三买
-   一卖、二卖、三卖
-   趋势背驰作为核心交易机制
-   Order Book作为策略输入
-   Funding Rate作为策略输入
-   OI作为策略输入
-   新闻/情绪作为策略输入
-   链上数据作为策略输入
-   LLM直接读取K线后自由生成买卖点
-   未来函数
-   使用未来已经确认的结构反推历史交易信号

# 2. 核心哲学：当下性

## 2.1 已完成结构与正在形成结构必须分离

系统同时维护：

``` text
Confirmed Structure
    已确认结构

Developing Structure
    正在形成结构
```

只有已经完成并满足定义的结构，才能进入：

-   笔
-   线段
-   中枢
-   走势类型
-   A序列

未完成结构只能作为：

-   Candidate
-   Developing
-   Observation

不得提前进入正式结构判断。

## 2.2 Agent不是价格预测器

Agent的任务不是：

> "预测下一根K线涨还是跌。"

而是：

> "截至当前1分钟K线，已经完成的缠论结构是什么？同级别分解运行到哪一步？根据当前状态应该BUY、SELL还是HOLD？"

因此系统属于：

**State-based Trading Agent**

而不是：

**Price Prediction Agent**

# 4. 分型引擎

## 4.1 K线包含关系

在形成分型之前，先处理K线包含关系。

定义：

``` text
当前K线被前一K线包含
或
前一K线被当前K线包含
```

需要根据当前方向进行合并。

系统必须保存：

``` python
RawCandle
ProcessedCandle
```

不能丢失原始K线。

原因：

> 交易最终需要落到真实K线上，而结构分析可能基于处理后的K线。

------------------------------------------------------------------------

## 4.2 顶分型

标准三K结构：

``` text
        High
          ▲
         / \
        /   \
       /     \
```

中间K线高点高于左右相邻有效K线，并满足缠论定义。

## 4.3 底分型

反向：

``` text
       \     /
        \   /
         \ /
          ▼
         Low
```

## 4.4 分型确认

分型不是"看起来像"就确认。

必须等待定义所要求的后续信息完成。

因此：

``` text
Candidate Fractal
        ↓
Confirmation
        ↓
Confirmed Fractal
```

只有：

``` text
Confirmed Fractal
```

才能：

-   成为有效笔端点候选
-   成为交易信号的最终定位点
-   成为结构止损锚点

------------------------------------------------------------------------

# 5. 分型与中继分型

分型不能简单按：

``` text
Top → Bottom → Top
```

机械生成笔。

例如：

``` text
顶分型
  ↓
立即底分型
  ↓
中间没有足够独立结构
```

两者不能因此直接形成有效笔。

如果之后：

``` text
Top2 > Top1
```

则前面的某些分型可能成为：

> 中继分型

最终有效笔可能从：

``` text
Bottom1 → Top2
```

形成。

因此：

**分型是笔的原材料，不等于笔。**

------------------------------------------------------------------------

# 6. 笔引擎

## 6.1 笔的核心原则

笔由符合定义的顶分型与底分型连接形成。

程序不得：

``` python
top + bottom = bi
```

简单处理。

必须经过：

1.  分型确认
2.  分型间独立性检查
3.  高低点关系
4.  必要的包含处理
5.  中继分型处理
6.  当前笔状态判断

------------------------------------------------------------------------

## 6.2 笔状态

系统必须保留以下四种状态：

``` text
(0,0)
(0,1)
(1,0)
(1,1)
```

v1.0中将其定义为**笔结构状态机的四种状态码**。

具体每个状态的语义必须在实现时严格对应所采用的原典版本/笔定义版本，不能凭经验重新解释。

建议数据结构：

``` python
BiState:
    code: tuple[int, int]
    start_fractal_id
    end_fractal_id
    direction
    status
```

# 7. 线段引擎

## 7.1 线段不是"三笔就结束"

"至少三笔"只是结构下限之一，不能写成：

``` python
if len(bi) >= 3:
    segment = True
```

线段必须按照特征序列方法划分。

## 7.2 特征序列

若线段从向上笔开始：

``` text
S1 X1 S2 X2 S3 X3 ...
```

其特征序列使用：

``` text
X1 X2 X3 ...
```

若线段从向下笔开始，则使用：

``` text
S1 S2 S3 ...
```

特征序列需要：

1.  构造
2.  非包含处理
3.  形成标准特征序列
4.  判断顶/底分型
5.  结合缺口条件确定线段终点

缠论第67课明确以特征序列及其标准化来精确定义线段划分。参见来源： -
https://www.ttyfp.com/chzhshch/16529.html -
https://www.fengmr.com/cld67ka.html

## 7.3 线段结束

原则：

> 出现符合定义的特征序列分型，是线段结束的重要前提；有缺口和无缺口的情况需要分别处理。

因此：

``` text
Feature Sequence
        ↓
Standard Feature Sequence
        ↓
Fractal
        ↓
Segment End Candidate
        ↓
Segment Confirmed
```

# 8. 中枢引擎

## 8.1 中枢

中枢是连续次级别走势类型之间的重叠区域。

系统至少需要保存：

``` python
Center:
    zg
    zd
    gg
    dd
    segments
    start_time
    end_time
    status
```

常用：

``` text
ZG = min(次级别走势高点中的相关上边界)
ZD = max(次级别走势低点中的相关下边界)
```

实际代码必须以统一的中枢区间定义实现，并通过单元测试验证。

------------------------------------------------------------------------

# 9. "至少五个线段"的工程理解

一个典型的：

``` text
进入中枢
+
中枢至少三个次级别走势类型
+
离开中枢
```

如果以线段作为次级别走势类型来观察，最小典型结构可以表示为：

``` text
L0  进入段
L1  中枢第1段
L2  中枢第2段
L3  中枢第3段
L4  离开段
```

因此：

``` text
典型最小结构 = 5个线段
```

同时：

``` text
每个线段至少由3笔构成
```

但必须注意：

> "5个线段"是这种典型进入---中枢---离开结构的最小表达，不应程序化为"所有1分钟走势必须恰好5段"。

中枢可以：

-   延伸
-   扩展
-   连接更多次级别走势

所以实际Ai可能远大于5个线段。

# 10. 1分钟走势类型 Ai

## 10.1 定义

本系统中：

> Ai = 1分钟操作级别上的一个完整走势类型。

Ai不是：

-   一笔
-   一条线段
-   一个分型
-   一根K线

而是更高一层的结构。

典型：

``` text
Ai
│
├── 进入段
├── 中枢
│   ├── 次级别走势1
│   ├── 次级别走势2
│   └── 次级别走势3
└── 离开段
```

## 10.2 Ai可以是

-   盘整走势
-   趋势走势

但本项目第一版的核心操作逻辑采用：

> **1分钟同级别分解 + 盘整背驰**

而不是围绕一买/二买/三买体系设计。

------------------------------------------------------------------------

# 11. 同级别分解

## 11.1 核心

把全部行情分解为：

``` text
A0 → A1 → A2 → A3 → ... → An
```

其中：

``` text
Ai = 1分钟级别走势类型
```

相邻Ai方向交替：

``` text
A0 ↑
A1 ↓
A2 ↑
A3 ↓
...
```

或：

``` text
A0 ↓
A1 ↑
A2 ↓
A3 ↑
...
```

## 11.2 不升级操作级别

即使发生：

``` text
1分钟中枢扩张
```

也不切换到：

``` text
5分钟
30分钟
```

而继续进行：

``` text
1分钟同级别分解
```

这正是本项目的核心工程选择。

------------------------------------------------------------------------

# 12. Ai序列不是静态序列

这是v1.0最重要的数据模型之一。

例如某一时刻：

``` text
A0
```

随着后续结构完成，发生扩张。

原来的分解可能重新表现为：

``` text
A0 + A1
```

因此：

``` text
A序列 = 动态确认结果
```

不是：

``` text
一次生成，永远不变
```

系统必须支持：

``` text
re-segmentation
```

即：

> 根据新增的已完成结构，对当前同级别分解重新确认。

# 13. 当下性

## 13.1 核心规则

在时间t：

``` text
Agent只能使用：

K[0:t]
```

不得使用：

``` text
K[t+1:]
```

即：

> 禁止任何形式的未来函数。

## 13.2 结构重算

每根1分钟K线完成：

``` text
New Candle
    ↓

    ↓
分型状态更新
    ↓
笔状态更新
    ↓
线段状态更新
    ↓
中枢状态更新
    ↓
走势类型更新
    ↓
A序列重新确认
    ↓
交易状态更新
```

## 14.1 多头：基本情况

假设：

``` text
A0 ↑
A1 ↓
A2 ↑
```

首先比较：

``` text
A2 vs A0
```

判断：

``` text
价格关系
+
力度关系
```

### 如果A2相对A0盘整顶背驰

``` text
SELL
```

### 如果A2没有盘整顶背驰

``` text
HOLD
```

# 15. 多头无盘背后的特殊状态

这是本项目必须严格实现的状态机。

假设：

``` text
A0 ↑
A1 ↓
A2 ↑
```

且：

``` text
A2 vs A0
无盘整顶背驰
```

继续：

``` text
A3 ↓
```

如果：

``` text
A3没有跌破A0高点
```

则：

``` text
HOLD
```

而且：

> **不能机械地把A4与A2立即作为普通盘整背驰比较。**

系统进入：

``` text
LONG_WAIT_BREAK
```

等待后续：

``` text
Ai+k+3
```

真正跌破：

``` text
Ai+k
```

对应高点。

这里：

``` text
k = 偶数
```

------------------------------------------------------------------------

# 16. 后续突破后的卖出

例如：

``` text
A0 ↑
A1 ↓
A2 ↑
A3 ↓
A4 ↑
A5 ↓
A6 ↑
```

并且：

``` text
A2 vs A0
无盘背

A3没有跌破A0高点

A5跌破A2高点
```

此时才进入：

``` text
A6
```

的最终判断。

比较：

``` text
A6 vs A4
```

如果：

``` text
A6不创新高
```

或者：

``` text
A6相对A4形成盘整顶背驰
```

则：

``` text
SELL
```

这一逻辑必须实现成状态机，而不能写成：

``` python
if current_A_vs_previous_same_direction_is_divergence:
    sell()
```

------------------------------------------------------------------------

# 17. 空头对称状态

如果：

``` text
A0 ↓
A1 ↑
A2 ↓
```

则：

``` text
A2 vs A0
```

判断盘整底背驰。

如果没有：

``` text
HOLD / KEEP SHORT
```

随后：

``` text
A3 ↑
```

如果：

``` text
A3不升破A0低点
```

继续持有空头。

直到：

``` text
Ai+k+3
```

升破：

``` text
Ai+k
```

对应低点。

然后：

``` text
Ai+k+4
```

如果：

``` text
不创新低
```

或者：

``` text
盘整底背驰
```

则：

``` text
COVER / BUY TO CLOSE
```

# 18. MACD力度引擎

MACD不负责定义：
