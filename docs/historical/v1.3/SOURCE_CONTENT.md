# ChanLun 1M Trading Agent 技术规格 v1.3

## 线段 → 1分钟走势中枢 → 1分钟走势类型 → 同级别分解基础状态机

> 版本：v1.3\
> 状态：可编码规格 / 待人工案例验收\
> 上级：v1.2\
> 固定操作级别：1分钟\
> 核心原则：**只在1分钟级别进行同级别分解，不向5分钟、30分钟等更高级别升级。**

# 1. v1.3的任务

v1.1：

``` text
K线
→ 分型
→ 笔
```

v1.2：

``` text
笔
→ 特征序列
→ 线段
```

v1.3：

``` text
线段

→ 1分钟走势类型
→ 走势连接
→ 同级别分解
→ A0、A1、A2……An
```

这一版开始真正进入你前面确定的交易框架。

最终系统不是：

``` text
1分钟
```

``` text
永远锁定1分钟
        ↓
把市场不断分解成
        ↓
A0 + A1 + A2 + ... + An
```

其中每一个：

``` text
Ai
```

都是一个**完整的1分钟级别走势类型**。

# 2. 为什么v1.3必须和普通缠论递归系统不同

普通缠论递归分析经常会继续讨论：

``` text
1分钟
→ 5分钟
→ 30分钟
→ 日线
```

但第38课明确指出，同级别分解可以固定在一个操作级别，把全部走势分解为该级别走势类型的连接；在该分解规则下，可以允许"盘整+盘整"的连接，而不需要把该级别的中枢延伸升级处理。citeturn1view1

第38课还明确指出：

> 在同级别分解中，如果次级别延伸出6段，可以把它作为两个同级别盘整类型连接。citeturn1view1

这正是本项目最重要的架构依据。

所以本项目固定：

``` text
操作级别 = 1分钟

1分钟级别：
    不定义“升级”
    允许盘整 + 盘整
    所有走势都继续拆成1分钟走势类型

1分钟以下：
    使用正常的中枢/线段递归规则

1分钟以上：
    完全不考虑
```

# 3. v1.3的核心定义

定义：

``` text
Ai = 一个完整的1分钟走势类型
```

它至少包含：

``` text
一个1分钟走势中枢
```

而一个走势中枢由：

``` text
至少三个连续次级别走势类型
```

的重叠部分确定。citeturn0search11turn0search7

在本系统中：

``` text
Ai
↓
至少一个中枢
↓
至少三个连续1分钟线段重叠形成的中枢结构
```

注意：

> **这里的"次级别走势类型"在我们的1分钟操作级别内部，是由线段继续构成的更细结构。**

因此在工程实现上：

``` text
Segment
```

是：

``` text
1分钟走势类型
```

内部构成中枢的最小高级结构单元。

------------------------------------------------------------------------

# 4. 关于"一个中枢至少五个线段"

这是本项目需要特别区分的地方。

中枢的定义核心是：

``` text
前三个连续次级别走势类型
```

产生重叠区间。

如果把：

``` text
进入中枢的线段
+
中枢内部形成重叠的线段
+
离开中枢的线段
```

全部作为一个完整走势结构来观察，典型最小完整形态可以表现为：

``` text
进入段
+
中枢第1段
+
中枢第2段
+
中枢第3段
+
离开段
```

即：

``` text
5个线段
```

但程序不能把：

``` text
5段
```

硬编码为：

``` python
if len(segments) == 5:
    center = True
```

正确做法是：

``` text
先根据中枢定义确定前三个连续次级别走势的重叠区间
再根据后续线段判断进入/延伸/离开
```

因此：

``` text
“五段”
```

是典型最小完整走势结构的直观表达，

而：

``` text
“三个连续次级别走势类型重叠”
```

才是程序真正应该实现的定义。citeturn0search11turn0search7

# 6. 中枢四个价格

对三个形成中枢的连续次级别走势：

``` text
S1
S2
S3
```

计算：

``` text
ZG = min(S1.high, S2.high, S3.high)
ZD = max(S1.low,  S2.low,  S3.low)
```

中枢成立要求：

``` text
ZG >= ZD
```

严格说，重叠区间为：

``` text
[ZD, ZG]
```

并且：

``` text
GG = max(S1.high, S2.high, S3.high)
DD = min(S1.low, S2.low, S3.low)
```

因此：

``` text
ZG
ZD
GG
DD
```

全部必须保存。

------------------------------------------------------------------------

# 7. 中枢不能只保存区间

后续判断：

``` text
延伸
新生
扩张
```

不能只看：

``` text
ZG / ZD
```

必须同时保存：

``` text
参与形成中枢的线段
后续围绕中枢波动的线段
每个线段与中枢的交集
每个线段的高低点
```

所以：

``` python
Center.members
```

必须保留完整引用。

``` text

    ↓
Segment S2
    ↓

    ↓

    ↓
Center C0
```

``` text

```

> 中枢"形成"与"后续走势已经结束"不是一个概念。

# 10. 中枢延伸

第20课明确区分了中枢延伸与新的同级别中枢/级别扩张。中枢延伸要求围绕中枢的后续次级波动继续与中枢区间保持规定的触及关系。citeturn0search7turn0search6

对程序来说：

``` text
当前Center C0
+
后续次级别线段/走势结构
```

如果仍然属于：

``` text
C0的延续
```

则：

``` text
Center.state = EXTENDING
```

并且：

``` text
C0.zg
C0.zd
```

作为原中枢核心区间继续保存。

# 11. 为什么本项目不在1分钟级别做"升级"

这是整个v1.3最关键的设计决定。

普通递归框架可能：

``` text
1m中枢延伸
→ 形成更大级别中枢
→ 升级到5m
```

但第38课给出的同级别分解规则允许：

``` text
同一级别的盘整 + 盘整
```

而不需要把它强行升级。citeturn1view1

因此：

``` text
1m Center扩张
```

在本项目中不输出：

``` text
5m Center
```

而输出：

``` text
Ai
+
Ai+1
```

即：

``` text
两个1分钟盘整走势类型连接
```

------------------------------------------------------------------------

# 12. "扩张"在本系统里的处理

假设原来市场当前看起来属于：

``` text
A0
```

随着新线段出现：

``` text
A0内部的中枢继续扩张
```

在普通级别递归思路中，可能产生：

``` text
更高级别中枢
```

本系统不升级。

而是：

``` text
A0
↓
发现新的1分钟级别走势类型分界
↓
A0 + A1
```

因此：

``` text
原来的一个Ai
```

可以因为同级别分解规则变成：

``` text
Ai + Ai+1
```

# 13. 关键原则：走势分解不是一次性静态完成

第38课强调，同级别分解和"当下性"紧密相关；对已完成走势可以进行分解，但交易时真正重要的是当前正在完成的走势。citeturn1view1

所以Agent不能：

``` text
等整个历史走势结束
→ 一次性切成A0...An
```

而必须：

``` text
每一根1分钟K线
→ 更新Segment
→ 更新Center
→ 更新当前Ai
→ 更新A0...An
→ 输出当前状态
```

# 18. Ai的类型

本系统暂时只需要：

``` text
CONSOLIDATION
TREND
```

判断依据：

``` text
一个Ai只有一个中枢
→ 盘整

一个Ai存在两个或以上同方向、非重叠的中枢
→ 趋势
```

但注意：

> 在同级别分解框架下，"中枢扩张"不产生新的更高级别Ai，而是可能产生新的同级别Ai连接。

------------------------------------------------------------------------

# 19. 盘整Ai

典型：

``` text
A0

    ┌─────┐
────│ C0  │────
    └─────┘
```

如果整个走势只有：

``` text
C0
```

则：

``` text
Ai.type = CONSOLIDATION
```

------------------------------------------------------------------------

# 20. 趋势Ai

如果：

``` text
C0
```

之后产生：

``` text
C1
```

并且：

``` text
C1与C0没有重叠
```

同时方向一致，则形成：

``` text
TREND
```

例如：

``` text
UP:

C0
      ↑
      │
      C1
          ↑
          C2
```

每个后续中枢必须满足同方向排列条件。

------------------------------------------------------------------------

# 21. 中枢新生

第20课明确区分：

``` text
原中枢延伸
```

和：

``` text
产生新的同级别中枢
```

如果新的中枢与前中枢没有重叠，则属于新的同级别中枢。citeturn0search7turn0search9

在程序中：

``` python
if new_center.does_not_overlap(old_center):
    NEW_CENTER
```

如果方向也满足趋势排列：

``` text
TREND_CONTINUATION
```

否则：

``` text
NEW_CONSOLIDATION
```

------------------------------------------------------------------------

# 22. 中枢扩张

第20课强调：

> 新中枢的波动如果触及前中枢延续时的瞬间波动区间，则不能简单认为形成了趋势，而是产生更大级别的中枢。citeturn0search7turn0search9

在本项目：

``` text
发现扩张
```

不创建：

``` text
5m Center
```

而是进入：

``` text
SAME_LEVEL_SPLIT
```

# 24. 为什么必须有SPLIT对象

因为：

``` text
历史回看
```

和：

``` text
当下
```

可能看到不同状态。

例如：

``` text
历史最终结果：

A0 + A1
```

但在：

``` text
K500
```

当下：

``` text
只有A0
```

所以系统必须允许：

``` text
A0
```

后来被：

``` text
A0 + A1
```

重新分解。

但：

> 重新分解不能改变当时Agent在K500时已经做出的交易决策。
