# v4.4.14 — Hyperliquid REST Read Path Implementation

## 1. Objective

v4.4.14 implements the first real Hyperliquid integration layer: read-only REST access through the Info endpoint.

No signed order, cancel, leverage mutation, or position-changing action is enabled by this release.

## 2. Implemented Components

### REST transport
src/chantrading/adapters/hyperliquid/rest.py

Provides:
- JSON POST transport;
- timeout;
- HTTP error capture;
- network error classification.

### Info client
src/chantrading/adapters/hyperliquid/info_client.py

Provides read-only methods for:
- meta;
- clearinghouseState;
- openOrders;
- userFills;
- orderStatus;
- candleSnapshot.

### Pure mappers
src/chantrading/adapters/hyperliquid/mappers.py

Converts venue dictionaries into canonical:
- Fill;
- Position;
- Position list.

Mappers perform no I/O.

## 3. Data Flow

The read path is:

    Hyperliquid REST /info
            ↓
    HyperliquidRestClient
            ↓
    HyperliquidInfoClient
            ↓
    Pure Mapper
            ↓
    Canonical Domain Model

No strategy or ChanLun module is allowed to consume raw venue payloads directly.

## 4. 1M Structural Data

The ChanLun structural path remains strictly 1-minute.

The Info client therefore exposes candleSnapshot with interval="1m" as the intended structural call.

The adapter does not automatically upgrade timeframe when a structure becomes difficult to interpret.

## 5. ETH Mapping

The read path accepts venue coin identifiers such as ETH.

Canonical project-level instrument identity remains ETH-USD.

The eventual instrument registry must own the ETH-USD ↔ venue coin mapping. It is intentionally not hard-coded into the ChanLun domain model.

## 6. Position Semantics

clearinghouseState is treated as authoritative venue state for reconciliation.

Position mapping preserves:
- signed position size;
- entry price;
- liquidation price when available;
- unrealized PnL;
- leverage value when available.

Missing values are represented as None rather than fabricated.

## 7. Fill Semantics

The mapper accepts the venue's compact side codes and canonical BUY/SELL forms.

Fill identity is retained through the venue trade identifier when available.

Duplicate suppression is NOT implemented in the mapper. That belongs to the event/state layer and will be addressed in later versions.

## 8. Order Status

orderStatus remains a raw read method in v4.4.14.

The next lifecycle layer must map the venue's detailed status/rejection vocabulary into the canonical order lifecycle defined in v4.4.12.

## 9. Error Boundary

Transport errors remain distinct from domain rejection.

Current categories:
- HTTP failure;
- network/URL failure;
- invalid response parsing;
- mapper validation error.

The full canonical venue-error mapper is deferred to the mutation/reconciliation implementation.

## 10. Tests

Added:
- Info request construction tests;
- clearinghouseState request test;
- fill mapper test;
- position mapper test.

These tests do not contact the live exchange.

## 11. Production Constraint

The real REST client exists, but this release does not automatically enable live trading.

Live read access should first pass:
- endpoint verification;
- schema fixtures;
- metadata drift checks;
- timestamp checks;
- deterministic replay tests.

## 12. Next Step

v4.4.15 should implement the WebSocket read path:

    WebSocket Connection
        ↓
    Subscription Manager
        ↓
    Heartbeat
        ↓
    Reconnect Supervisor
        ↓
    Raw Event Router
        ↓
    Canonical Market/User Events

Priority streams:
1. 1m candle;
2. order updates;
3. user fills;
4. clearinghouse/account state where supported;
5. open-order synchronization.

The WebSocket layer must enter RESYNCING after reconnect and must not return READY until state synchronization has completed.

## 13. Scope Boundary

v4.4.14 is a read-path implementation.

It does not certify:
- live order submission;
- stop execution;
- reduce-only protection;
- liquidation protection;
- production capital.

Those remain downstream certification gates.
