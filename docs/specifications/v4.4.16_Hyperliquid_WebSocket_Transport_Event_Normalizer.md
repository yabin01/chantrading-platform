# v4.4.16 — Hyperliquid WebSocket Transport & Event Normalizer

## 1. Objective

v4.4.16 converts the v4.4.15 WebSocket lifecycle design into a testable transport and normalization layer.

Implemented:
- injectable WebSocket transport;
- raw event router;
- 1m candle normalizer;
- user-fill normalizer;
- order-update normalizer;
- canonical event envelope tests.

No signed mutation is enabled.

## 2. Venue Evidence

## 3. New Modules

### transport.py

Defines the injectable WebSocketTransport protocol.

An InMemoryWebSocketTransport is included for deterministic tests.

The production network client remains isolated from normalization logic.

### normalizers.py

Provides pure conversion functions:
- normalize_candle;
- normalize_user_fills;
- normalize_order_updates;
- normalize_message.

They return AdapterEvent objects.

### router.py

HyperliquidEventRouter receives raw messages, normalizes them and emits canonical events.

## 4. 1M Candle Normalization

The normalizer preserves:
- instrument;
- interval;
- open time;
- close time;
- OHLC;
- volume;
- final flag.

All numeric prices/volumes are converted to Decimal.

This prevents binary floating-point representation from entering the ChanLun structural path.

## 5. Final Candle Rule

The event carries venue close time and a provisional final flag.

The final structural-candle policy remains a state-layer concern.

A candle event MUST NOT be interpreted as a completed ChanLun K-line merely because a message was received.

The downstream candle aggregator is responsible for enforcing the project's completed-1m-bar rule.

## 6. Fill Normalization

Each fill receives a deterministic event ID derived from the strongest available venue identity:
- tid;
- hash;
- oid fallback.

The fill remains raw at this layer.

Canonical Fill mapping and duplicate application protection belong to the event/state layer.

## 7. Order Update Normalization

Order update payloads are preserved inside AdapterEvent.data.

The normalizer extracts a stable event ID from:
- order ID;
- status.

Detailed status translation into the canonical OrderStatus lifecycle is intentionally deferred to v4.4.18.

## 8. Raw Event Preservation

Every AdapterEvent keeps:
- normalized data;
- raw source message.

This is required for:
- forensic analysis;
- replay;
- parser regression tests;
- venue schema changes.

## 9. Transport Separation

The architecture is now:

    WebSocketTransport
           ↓
    Raw Message
           ↓
    HyperliquidEventRouter
           ↓
    Normalizer
           ↓
    AdapterEvent
           ↓
    State Store / Event Bus

The transport does not know ChanLun.

The normalizer does not know trading policy.

## 10. Determinism

Normalizers are pure functions except for receive_time_ms supplied by the caller.

This means the same captured raw message and timestamp must produce the same canonical event.

This is a prerequisite for deterministic replay.

## 11. Backpressure

The current router emits synchronously.

A bounded asynchronous event bus is intentionally deferred to the runtime/state-store layer.

The production runtime must never silently drop fills or order updates because the consumer is slow.

## 12. Tests

Added unit coverage for:
- 1m candle normalization;
- Decimal conversion;
- final candle calculation;
- user fill normalization;
- deterministic fill event identity.

## 13. Current Limitation

The implementation does not yet open a real network WebSocket.

This is deliberate.

The next layer must first add:
- production WebSocket transport;
- ping/pong;
- reconnect;
- subscription replay;
- error handling;
- connection metrics.

Only then should live market/user events be admitted to the production runtime.
