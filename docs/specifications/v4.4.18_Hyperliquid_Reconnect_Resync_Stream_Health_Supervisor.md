# v4.4.18 — Reconnect, Resync & Stream Health Supervisor

## 1. Objective

v4.4.18 adds the project-level control plane for WebSocket failure recovery.

It separates:
- transport reconnect;
- retry policy;
- stream health;
- REST-authoritative resynchronization;
- READY authorization.

## 2. Why This Layer Exists

The current Hyperliquid SDK already supports automatic reconnection and subscription replay. The official Python SDK sends periodic pings and replays queued subscriptions when the socket opens. citeturn0search0

A newer Hyperliquid TypeScript SDK also documents bounded retries, exponential backoff and automatic resubscription. citeturn0search1

ChanTrading nevertheless requires an additional layer because a connected WebSocket is not equivalent to a reconciled trading state.

## 3. Components

### reconnect.py

Defines ReconnectPolicy:
- max attempts;
- exponential backoff;
- maximum delay;
- jitter;
- attempt admission.

### health.py

Defines:
- HEALTHY;
- DEGRADED;
- STALE;
- RESYNCING.

Health tracks:
- latest event;
- latest pong;
- health counters.

### resync.py

ResyncCoordinator obtains authoritative REST snapshots:
- clearinghouseState;
- openOrders;
- userFills.

The snapshot is returned as a ResyncResult and is not silently merged into strategy state.

### supervisor.py

StreamSupervisor coordinates:
- disconnect;
- RESYNCING;
- health;
- REST resync;
- READY authorization.

## 4. Recovery State Machine

Normal:

CONNECTED
→ HEALTHY
→ READY

Failure:

CONNECTED
→ DISCONNECTED
→ RESYNCING
→ reconnect
→ REST snapshot
→ consistency checks
→ READY

Persistent failure:

RESYNCING
→ DEGRADED
→ STALE

No production trading authorization is allowed while the system is RESYNCING or STALE.

## 5. Backoff

Default policy:

- attempt 1: approximately 1s;
- attempt 2: approximately 2s;
- attempt 3: approximately 4s;
- continue exponentially;
- cap at 30s;
- add bounded jitter.

The exact delay is intentionally policy-controlled and deterministic under a supplied RNG for tests.

## 6. Health Model

The system monitors both:
- transport liveness through pong;
- application liveness through data events.

Therefore:

socket alive + no market events
!=
healthy market stream.

Similarly:

market events alive + no pong
!=
fully healthy transport.

## 7. REST Authority

During resync, REST is authoritative for account state.

Current snapshot set:
- clearinghouseState;
- openOrders;
- userFills.

This is the beginning of the reconciliation pipeline.

## 8. No Blind Replay

The system does NOT assume that reconnect + resubscribe automatically repairs state.

Automatic subscription replay restores the stream, but does not prove that no events were missed during the outage.

Therefore ChanTrading performs an explicit REST snapshot before returning READY.

## 9. Trading Safety Rule

While:

RESYNCING
DEGRADED
STALE

the system must not authorize new production orders.

This is an execution-safety invariant, not a UI status.

## 10. Important Implementation Limitation

The current v4.4.18 ResyncCoordinator collects authoritative snapshots but does not yet perform full historical gap reconciliation.

That requires:
- snapshot normalization;
- local state comparison;
- duplicate detection;
- fill ledger reconciliation;
- open-order reconciliation;
- position reconciliation;
- event cutoff timestamps.

Those belong in the next reconciliation layer.

## 12. Next Step

v4.4.19 should implement canonical order mutation through the Hyperliquid Exchange API.

Before that happens, v4.4.19 must explicitly define:
- order request;
- signing boundary;
- nonce;
- expiresAfter;
- client order identity;
- reduce-only;
- post-only;
- trigger orders;
- timeout;
- UNKNOWN result;
- idempotent retry policy.

The official SDK separates read-only Info from signed Exchange actions and requires a wallet for Exchange operations. citeturn0search2

## 13. Production Boundary

v4.4.18 does not submit, cancel, modify or close positions.

Its purpose is to ensure that the system can detect and recover from stream failure before signed execution is introduced.
