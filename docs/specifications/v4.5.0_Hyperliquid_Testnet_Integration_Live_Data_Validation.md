# v4.5.0 — Hyperliquid Testnet Integration & Live Data Validation

## 1. Objective

v4.5.0 begins real Testnet integration.

The purpose is to validate the complete runtime boundary using real venue data while keeping Mainnet production authorization impossible.

## 2. Scope

Initial validation targets:

- Hyperliquid Testnet endpoint separation;
- 1-minute candle ingestion;
- candle timestamp continuity;
- ChanLun input compatibility;
- Testnet execution authorization;
- downstream reconciliation compatibility.

## 3. Network Boundary

The Testnet adapter requires an explicit TESTNET network value.

MAINNET configuration is rejected by the Testnet boundary.

This prevents accidental routing of a Testnet integration component into production.

## 4. 1m Candle Contract

ChanLun validation uses:

    symbol
    interval = 1m
    timestamp
    open
    high
    low
    close
    volume

The initial validator requires consecutive candles to be exactly 60,000 ms apart.

A gap is not silently filled.

A production ingestion layer should instead emit a data-quality event and obtain the missing candle through an authoritative recovery path.

## 5. Data Validation Pipeline

    WebSocket candle
          ↓
    schema validation
          ↓
    timestamp validation
          ↓
    continuity validation
          ↓
    deduplication
          ↓
    canonical market event
          ↓
    ChanLun Engine

## 6. Missing Candle Rule

If:

    T[n] - T[n-1] != 60s

the market stream is considered incomplete.

The system must not invent OHLC values.

The system should:
1. mark the stream as degraded;
2. request/recover the missing interval;
3. revalidate continuity;
4. only then restore the normal ChanLun calculation path.

## 7. Duplicate Candle Rule

A duplicate timestamp must not create a second canonical market event.

The canonical event identity is:

    symbol + interval + timestamp

## 8. ChanLun Boundary

v4.5.0 does not change the ChanLun rules.

It only establishes the venue-to-engine input boundary.

The downstream engine remains responsible for:
- 分型;
- 笔;
- 线段;
- 中枢;
- 走势结构;
- 背驰;
- Decision Engine state.

## 9. Execution Boundary

Testnet execution may be authorized by the TestnetExecutionGate.

This does not grant Mainnet authorization.

Mainnet still requires the v4.4.23 certification gates and an independently approved production configuration.

## 10. Position / Order Validation

After the first Testnet order path is connected, every mutation must flow through:

    Decision
       ↓
    Risk
       ↓
    Order Request
       ↓
    Signing Gateway
       ↓
    Testnet Exchange
       ↓
    Order Lifecycle
       ↓
    Fill
       ↓
    Reconciliation
       ↓
    State Store

No direct exchange call should bypass these boundaries.

## 11. Testnet Validation Phases

### Phase A — Market Data

- connect WebSocket;
- subscribe to ETH 1m candles;
- validate timestamps;
- validate OHLCV;
- detect gaps;
- detect duplicates;
- persist canonical events.

### Phase B — ChanLun Replay

- feed canonical 1m candles;
- verify deterministic state transitions;
- compare live state against replay;
- verify no future-bar leakage.

### Phase C — Order Lifecycle

- create Testnet order;
- observe acknowledgement;
- observe open/resting state;
- observe fill/cancel;
- reconcile against authoritative state.

### Phase D — Recovery

- disconnect WebSocket;
- reconnect;
- recover snapshot;
- reconcile;
- resume only after consistency.

### Phase E — Extended Run

- continuous Testnet operation;
- collect latency;
- collect reconnect count;
- collect data gaps;
- collect reconciliation events;
- collect order/fill lifecycle evidence.

## 12. Metrics

The Testnet runtime should record:

- candle_gap_count;
- candle_duplicate_count;
- websocket_disconnect_count;
- reconnect_duration_ms;
- order_ack_latency_ms;
- fill_latency_ms;
- reconciliation_drift_count;
- unknown_order_count;
- recovery_success_count;
- recovery_failure_count.

## 13. Acceptance Criteria

The first Testnet milestone is accepted only when:

1. 1m candle stream remains structurally valid;
2. gaps are detected rather than fabricated;
3. duplicate events are idempotent;
4. ChanLun replay is deterministic;
5. order lifecycle reaches a terminal state correctly;
6. fills are reconciled exactly once;
7. position equals authoritative Testnet state after reconciliation;
8. disconnect recovery blocks trading until consistency;
9. no Mainnet endpoint is reachable from the Testnet execution configuration.

## 14. Current Implementation

This commit establishes:

- TestnetConfig;
- explicit Testnet network validation;
- 1m candle contract;
- candle continuity validation;
- Testnet execution gate;
- unit tests for network separation and candle continuity.

Actual WebSocket subscription and signed Testnet order integration remain the next implementation step.

## 15. Next Step

v4.5.1 should implement the real Hyperliquid Testnet WebSocket market-data transport.

It should consume live 1m candles, normalize them into the existing Event Schema, persist them into State Store, and provide deterministic replay input to the ChanLun Engine.

## 16. Production Boundary

v4.5.0 is Testnet-only.

No component introduced here authorizes Mainnet trading.
