# v4.5.10 — Production Watchdog, Backoff & Runtime Event Safety\n\n## 1. Objective\nv4.5.10 adds runtime self-monitoring for extended Testnet execution.\n\nThe watchdog covers:\n- heartbeat freshness;\n- bounded reconnect attempts;\n- exponential reconnect backoff;\n- recovery timeout;\n- safety freeze;\n- watchdog halt events.\n\n## 2. Heartbeat Safety\nIf the latest accepted heartbeat exceeds the configured freshness budget, the watchdog emits HEARTBEAT_MISSED and freezes trading.\n\nHeartbeat loss is treated as a runtime safety condition, not merely an observability warning.\n\n## 3. Reconnect Backoff\nReconnect delay follows bounded exponential backoff:\n\n    delay = min(max_delay, base_delay × 2^attempt)\n\nExample default sequence:\n\n    1s → 2s → 4s → 8s → ... → 30s\n\nThe purpose is to prevent reconnect storms.\n\n## 4. Maximum Attempts\nThe watchdog limits reconnect attempts.\nOnce the configured maximum is exceeded:\n\n    WATCHDOG_HALTED\n\nis emitted and trading remains disabled.\n\n## 5. Recovery Timeout\nRecovery cannot remain indefinitely in an ambiguous state.\nIf recovery exceeds the configured timeout:\n\n    RECOVERY_TIMEOUT\n          ↓\n       FREEZE\n\nThe runtime must remain frozen until an operator or higher-level recovery controller establishes a consistent state.\n\n## 6. Runtime Events\nv4.5.10 establishes these canonical runtime event types:\n- HEARTBEAT_MISSED;\n- RECONNECT_SCHEDULED;\n- RECOVERY_TIMEOUT;\n- SAFETY_FREEZE;\n- WATCHDOG_HALTED.\n\nThese events should later be persisted through the project's Event Schema so runtime failures are replay-visible.\n\n## 7. Reset Rule\nReconnect attempt counters are reset only after successful recovery.\nA socket reconnect alone does not reset the safety state.\n\n## 8. Testnet Soak Test Contract\nFor an extended Testnet run, the runtime should record:\n- watchdog events;\n- heartbeat gaps;\n- reconnect attempts and delays;\n- recovery durations;\n- reconciliation drift;\n- order/fill lifecycle;\n- halted periods.\n\n## 9. Acceptance Criteria\n1. heartbeat loss freezes trading;\n2. reconnect uses bounded exponential backoff;\n3. reconnect attempts are capped;\n4. recovery timeout freezes the runtime;\n5. watchdog halt cannot silently resume trading;\n6. successful recovery resets reconnect state;\n7. runtime safety events are deterministic.\n\n## 10. Next Step\nv4.5.11 should add the extended Testnet soak-test runner and machine-readable runtime report.\n\nThe report should support at least:\n- start/end timestamps;\n- uptime;\n- orders;\n- fills;\n- reconnects;\n- recoveries;\n- drift events;\n- watchdog events;\n- halted duration;\n- replay-equivalence result.\n\n## 11. Production Boundary\nv4.5.10 remains Testnet-only. It adds runtime safety mechanisms but does not authorize Mainnet execution.
