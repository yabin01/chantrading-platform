# v4.5.12 — Executable Testnet Soak Runner & Certification Checklist\n\n## 1. Objective\nv4.5.12 turns the v4.5.11 soak-test report contract into an executable runner.\n\nThe runner controls a bounded test interval and records runtime events into the machine-readable SoakMetrics report.\n\n## 2. Runner Lifecycle\nSTART → RUNNING → STOP\n\nDuring RUNNING the harness accepts:\n- order events;\n- fill events;\n- reconnect events;\n- recovery events;\n- drift events;\n- watchdog events;\n- replay-equivalence result.\n\nAfter STOP, event recording is rejected.\n\n## 3. Duration Control\nSoakRunConfig defines a positive duration_ms.\nThe runner exposes should_stop() so an outer runtime loop can terminate deterministically.\n\nScheduling, networking and exchange I/O remain outside the recorder itself.\n\n## 4. Event Integration\nThe runner is intentionally an orchestration boundary.\nExisting runtime components should call the corresponding record_* method when their authoritative event occurs.\n\nExamples:\n\n    Order accepted  → record_order()\n    Fill confirmed  → record_fill()\n    Socket reconnect → record_reconnect()\n    Recovery passed → record_recovery()\n    Drift detected   → record_drift()\n    Watchdog event   → record_watchdog()\n\n## 5. Replay Certification\nBefore a run is marked successful, the Event Store must be replayed into a clean state and compared with the final runtime state.\nThe runner records the resulting boolean as replay_equivalent.\n\n## 6. Testnet Certification Checklist\n### A. Runtime\n- [ ] Runtime started cleanly\n- [ ] Heartbeat remained observable\n- [ ] No unbounded reconnect loop\n- [ ] Watchdog remained deterministic\n\n### B. Execution\n- [ ] Every submitted order has an authoritative lifecycle\n- [ ] Every fill is accounted for\n- [ ] Final position reconciles with venue state\n- [ ] No unresolved UNKNOWN order remains\n\n### C. Recovery\n- [ ] At least one controlled disconnect was recovered\n- [ ] Recovery froze new execution\n- [ ] Reconciliation passed before resume\n- [ ] Failed recovery remained halted\n\n### D. Replay\n- [ ] Event log persisted\n- [ ] Clean State Store rebuilt\n- [ ] Replay completed\n- [ ] replay_equivalent = true\n\n### E. Report\n- [ ] JSON report archived\n- [ ] Event log archived\n- [ ] Final venue snapshot archived\n- [ ] No unresolved drift\n\n## 7. Run Levels\nRecommended certification progression:\n\n    30 min → 2 h → 24 h → 72 h → 7 d\n\nEach level requires the previous level to satisfy the checklist.\n\n## 8. Important Boundary\nPassing a Testnet soak run proves operational behavior under the tested conditions only.\nIt does not prove profitability, strategy quality, market robustness or Mainnet safety.\n\n## 9. Next Step\nv4.5.13 should connect the runner to the real Runtime event bus and persistence layer, then add a CLI entry point for starting and exporting a soak run.\n\n## 10. Production Boundary\nv4.5.12 remains Testnet-only.
