# v4.5.13 — Runtime Event Bus, Persistence Boundary & Soak CLI\n\n## 1. Objective\nv4.5.13 connects the previously isolated runtime components through a deterministic in-process event bus and exposes a minimal command-line entry point for bounded Testnet soak runs.\n\n## 2. Runtime Event Bus\nThe RuntimeEventBus provides:\n- named event subscriptions;\n- deterministic publication order;\n- event history for the current process;\n- explicit event payloads and timestamps.\n\nCanonical runtime events currently wired to soak metrics:\n- ORDER_ACCEPTED;\n- FILL_CONFIRMED;\n- WS_RECONNECTED;\n- RECOVERY_COMPLETED;\n- RECONCILIATION_DRIFT;\n- WATCHDOG_EVENT.\n\n## 3. Soak Runtime\nSoakRuntime composes:\n\n    RuntimeEventBus\n          ↓\n    event-to-metric adapter\n          ↓\n    SoakTestRunner\n          ↓\n    SoakTestRecorder\n          ↓\n    canonical JSON report\n\nThe event bus does not own exchange logic and does not mutate trading state.\n\n## 4. CLI\nA minimal `chantrading-soak` CLI is provided using Python's standard `argparse` module.\nSupported arguments:\n- --duration-ms;\n- --start-ms;\n- --end-ms.\n\nThe CLI creates a bounded soak run and emits a machine-readable JSON report.\n\n## 5. Persistence Boundary\nv4.5.13 deliberately keeps the event bus in-process.\nDurable Event Store persistence remains the responsibility of the project's existing State Store/Event Schema layer.\n\nTherefore:\n\n    Runtime Event\n         ↓\n    Event Bus\n         ↓\n    Event Store adapter\n         ↓\n    durable event log\n\nshould be the next integration boundary.\n\n## 6. Safety Boundary\nThe event bus is observational for soak metrics.\nIt cannot:\n- submit orders;\n- cancel orders;\n- alter positions;\n- bypass reconciliation;\n- bypass recovery;\n- enable trading.\n\nThis preserves the existing safety hierarchy.\n\n## 7. Acceptance Criteria\nv4.5.13 is accepted when:\n1. runtime events can be published deterministically;\n2. subscribed metric handlers receive events in publication order;\n3. soak metrics reflect authoritative runtime events;\n4. CLI can start and finish a bounded run;\n5. CLI output is machine-readable JSON;\n6. event wiring does not directly mutate trading state;\n7. durable persistence remains separated behind the Event Store boundary.\n\n## 8. Next Step\nv4.5.14 should implement the durable Event Store adapter for runtime events, then add report artifact persistence and a complete Testnet certification command.\n\n## 9. Production Boundary\nv4.5.13 remains Testnet-only and contains no Mainnet enablement.
