# v4.5.1 — Hyperliquid Testnet WebSocket Market Data Transport\n\n## 1. Objective\nv4.5.1 implements the first real-time market-data transport boundary for Hyperliquid Testnet. The scope is deliberately limited to market data. No order mutation is introduced.\n\n## 2. Endpoint\nTestnet WebSocket: wss://api.hyperliquid-testnet.xyz/ws\nThe endpoint is hard-bound to the Testnet adapter and cannot be supplied by the Mainnet execution path.\n\n## 3. Candle Subscription\nCanonical subscription: { method: subscribe, subscription: { type: candle, coin: ETH, interval: 1m } }\nOnly 1m is accepted by this ChanLun integration boundary.\n\n## 4. Canonical Candle Event\nCandleEvent contains coin, interval, timestamp, open, high, low, close and volume.\nNumeric values remain strings at the transport boundary to avoid binary floating-point mutation. Decimal conversion belongs to the downstream canonical market-data layer.\n\n## 5. Transport Flow\nTestnet WebSocket → raw message → JSON decode → channel check → candle validation → CandleEvent → Event Normalizer → State Store → ChanLun Engine.\n\n## 6. Non-Candle Messages\nThe candle parser rejects messages whose channel is not candle. This prevents unrelated WebSocket traffic from entering the ChanLun market-data path.\n\n## 7. Connection Boundary\nWebSocketMarketDataTransport owns connection creation, subscription transmission, message parsing, normalized candle forwarding and connection state.\nIt does not calculate indicators, construct ChanLun structures, make trading decisions, sign orders or submit orders.\n\n## 8. Reconnect Boundary\nv4.5.1 exposes connection state but does not duplicate the full reconnect/resync controller from v4.4.18.\nThe production controller remains responsible for DISCONNECTED → CONNECTING → SUBSCRIBING → STREAMING → RESYNCING → STREAMING.\nAfter reconnect, downstream reconciliation must decide when the market-data stream is safe for ChanLun calculation.\n\n## 9. Data Quality\nThe transport layer does not fabricate candles. Missing timestamps, duplicates, stale events and out-of-order events must be handled by the canonical market-data/event layer.\n\n## 10. Tests\nAdded tests for candle payload parsing, 1m subscription generation, rejection of non-1m subscriptions, Testnet endpoint selection and normalized candle forwarding.\n\n## 11. Security\nNo API key, wallet key, signature or account credential is required for this market-data transport. The market-data WebSocket must remain usable without granting execution authority.\n\n## 12. Next Step\nv4.5.2 should connect this transport to the existing Event Schema and State Store: canonical event ID, event timestamp, sequence/order validation, duplicate suppression, gap detection, persistence and deterministic replay input.\n\n## 13. Production Boundary\nv4.5.1 is market-data only and Testnet-only. It cannot submit an order and cannot authorize Mainnet trading.
