# v4.5.2 — Canonical Market Event & State Store Integration\n\n## 1. Objective\nv4.5.2 establishes the canonical bridge from Hyperliquid Testnet 1m candles into the project's Event Schema / State Store boundary.\n\n## 2. Canonical Event Identity\nEvent identity is deterministic:\n\n    SHA256(source | symbol | interval | timestamp)\n\nFor Testnet:\n\n    source = hyperliquid.testnet\n    interval = 1m\n\nThis makes the same venue candle resolve to the same event ID during live ingestion and deterministic replay.\n\n## 3. Canonical Market Event\nThe normalized event contains:\n- event_id;\n- source;\n- symbol;\n- interval;\n- timestamp;\n- open;\n- high;\n- low;\n- close;\n- volume;\n- schema_version.\n\n## 4. Duplicate Rule\nIf an event ID has already been observed, the event is classified as DUPLICATE.\nA duplicate must not produce a second State Store mutation.\n\n## 5. Out-of-Order Rule\nIf a candle timestamp is earlier than the latest accepted timestamp for the symbol, the event is classified as OUT_OF_ORDER.\nIt is not silently inserted into the live sequence.\n\nHistorical replay may process explicitly ordered historical data, but live ingestion must preserve the canonical event order.\n\n## 6. Gap Rule\nIf:\n\n    timestamp > previous_timestamp + 60s\n\nthe event is classified as GAP.\nThe event is retained as observed evidence, but the ChanLun calculation path must not assume that the missing candle exists.\n\nGap recovery is a separate operation.\n\n## 7. State Store Boundary\nThe intended path is:\n\n    WebSocket\n       ↓\n    CandleEvent\n       ↓\n    CanonicalMarketEvent\n       ↓\n    MarketEventGuard\n       ↓\n    State Store append\n       ↓\n    Replay log\n       ↓\n    ChanLun Engine\n\nThe MarketEventGuard does not mutate the State Store itself; it determines whether an event is safe to append.\n\n## 8. Deterministic Replay\nGiven the same ordered canonical event sequence, the State Store replay input must be identical.\nThis provides the foundation for comparing:\n\n    LIVE STATE\n        vs\n    REPLAY STATE\n\nAny divergence becomes a deterministic-replay defect rather than an exchange-data ambiguity.\n\n## 9. Important Boundary\nv4.5.2 does not yet implement automatic gap recovery.\nIt detects the gap and prevents the system from pretending the sequence is complete.\n\n## 10. Tests\nAdded tests for:\n- deterministic event IDs;\n- canonical conversion;\n- duplicate idempotency;\n- gap detection;\n- out-of-order detection.\n\n## 11. Next Step\nv4.5.3 should implement State Store append/replay integration and a live-vs-replay equivalence harness.\n\nThe acceptance target is:\n\nsame 1m event sequence → same replayed state\n\nwith no hidden wall-clock, network, or mutable external dependency.\n\n## 12. Production Boundary\nv4.5.2 remains Testnet market-data infrastructure and cannot authorize Mainnet execution.
