# v4.5.4 — Hyperliquid Testnet Execution Lifecycle Integration

## 1. Objective

v4.5.4 connects the previously isolated Order Manager / Signing Gateway boundary to a deterministic Testnet order lifecycle model.

This version validates order-state behavior before introducing a live signed-order transport.

## 2. Lifecycle

    CREATED
       ↓
    SIGNING
       ↓
    SUBMITTED
       ↓
    OPEN
       ↓
    FILLED

Alternative terminal paths:

    SUBMITTED → REJECTED
    OPEN → CANCELED

Uncertainty path:

    SUBMITTED → UNKNOWN

UNKNOWN is not a rejection.

## 3. UNKNOWN Safety Rule

An UNKNOWN order cannot transition back to CREATED.

Therefore:

    timeout
      ↓
    UNKNOWN
      ↓
    authoritative lookup

and never:

    UNKNOWN
      ↓
    create second order

This protects against duplicate execution after a network timeout.

## 4. Client Order Identity

Each Testnet order request requires a unique client_order_id within the local lifecycle domain.

Duplicate client_order_id creation is rejected.

## 5. Terminal State Rule

FILLED, CANCELED and REJECTED are terminal states.

A terminal order cannot be changed into a different terminal or non-terminal state.

## 6. Execution Boundary

The intended runtime path is:

    ChanLun Decision
          ↓
        Risk
          ↓
     Order Request
          ↓
      Order Manager
          ↓
    Signing Gateway
          ↓
     Testnet Exchange
          ↓
     Order Updates
          ↓
        Fill
          ↓
    Reconciliation

The Testnet execution lifecycle does not calculate trading signals.

## 7. Position Boundary

A FILLED order is not by itself the final position truth.

After execution, the system must reconcile the resulting position against the authoritative venue state before considering execution state consistent.

## 8. Reduce-Only

The order request model carries reduce_only explicitly.

This flag must not be inferred from the current position at execution time because doing so can introduce a race between decision and submission.

## 9. Tests

Added tests for:
- full CREATED → SIGNING → SUBMITTED → OPEN → FILLED lifecycle;
- UNKNOWN retry prevention;
- terminal-state immutability;
- duplicate client-order-ID rejection.

## 10. Current Limitation

v4.5.4 currently implements the deterministic lifecycle boundary.

It does not yet send real signed Testnet orders.

The live signing and submission connector remains the next integration step after validating request mapping and signing isolation.

## 11. Acceptance Criteria

Before real Testnet mutation is enabled:
1. every order has a unique client identity;
2. UNKNOWN cannot be blindly retried;
3. terminal states are immutable;
4. fills are reconciled before execution state is certified;
5. Mainnet cannot be selected through this Testnet path.

## 12. Next Step

v4.5.5 should implement real Testnet order submission through the existing Signing Gateway, followed by live order updates and fill ingestion.

## 13. Production Boundary

v4.5.4 remains Testnet-only and does not authorize Mainnet execution.
