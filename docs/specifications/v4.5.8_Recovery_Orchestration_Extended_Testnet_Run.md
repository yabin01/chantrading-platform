# v4.5.8 — Recovery Orchestration & Extended Testnet Run\n\n## 1. Objective\nv4.5.8 defines deterministic recovery after WebSocket disconnects, process restarts, UNKNOWN orders or reconciliation drift.\n\n## 2. Recovery State Machine\nHEALTHY → FREEZE → SNAPSHOT → REBUILD → RECONCILE → REPLAY_VERIFY → RESUME\n\nFailure path:\n\n    any unresolved recovery condition\n             ↓\n          HALTED\n\nTrading is disabled from FREEZE until RESUME.\n\n## 3. Freeze Rule\nWhen recovery is triggered:\n- no new opening orders may be created;\n- existing UNKNOWN orders are not blindly retried;\n- market-data ingestion may continue or restart independently;\n- recovery becomes the only path capable of re-enabling trading.\n\n## 4. Snapshot\nThe runtime obtains authoritative Testnet execution facts before rebuilding local execution state.\nAt minimum the recovery snapshot must cover open orders, relevant order status, recent fills and current position state.\n\n## 5. Rebuild\nLocal execution state is reconstructed from the authoritative snapshot and the persisted event history.\nThe rebuild step must not create new exchange orders.\n\n## 6. Reconciliation\nThe rebuilt state is compared with the venue snapshot using the v4.5.7 ReconciliationEngine.\nAny unresolved drift moves the runtime to HALTED.\n\n## 7. Replay Verification\nAfter reconciliation, the recovered state is replayed through the deterministic event path.\nRecovery can resume only when replay verification succeeds.\n\n## 8. Resume Gate\nRESUME is not a manual shortcut. The required sequence is:\n\n    FREEZE\n      ↓\n    SNAPSHOT\n      ↓\n    REBUILD\n      ↓\n    RECONCILE = CONSISTENT\n      ↓\n    REPLAY_VERIFY = PASS\n      ↓\n    RESUME\n\nAny skipped stage must be treated as an unsafe recovery.\n\n## 9. Failure Injection Targets\nExtended Testnet validation should deliberately simulate:\n- WebSocket disconnect;\n- process restart;\n- delayed order acknowledgement;\n- UNKNOWN submission result;\n- duplicate fill message;\n- missing local fill;\n- position mismatch;\n- replay mismatch.\n\nThe expected safety result is freeze or halt, never an unverified new order.\n\n## 10. Tests\nAdded tests for successful recovery, reconciliation failure halting and replay-verification failure halting.\n\n## 11. Next Step\nv4.5.9 should add an extended Testnet runtime harness with heartbeat, reconnect, snapshot polling, metrics and failure-injection controls.\n\n## 12. Production Boundary\nv4.5.8 remains Testnet-only. Recovery success does not authorize Mainnet execution.
