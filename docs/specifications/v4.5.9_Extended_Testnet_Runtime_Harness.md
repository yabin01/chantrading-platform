# v4.5.9 — Extended Testnet Runtime Harness\n\n## 1. Objective\nv4.5.9 introduces the first runtime-level harness for sustained Hyperliquid Testnet validation.\n\nThe harness coordinates:\n- heartbeat monitoring;\n- WebSocket disconnect/reconnect state;\n- recovery invocation;\n- runtime metrics;\n- order/fill counters;\n- reconciliation drift reaction;\n- explicit stop behavior.\n\n## 2. Runtime State\nSTARTING → RUNNING\n\nRUNNING → DEGRADED → RECOVERING → RUNNING\n\nRUNNING → DEGRADED → RECOVERING → HALTED\n\nSTOPPED is a terminal operator-controlled state for the current runtime instance.\n\n## 3. Trading Safety\nTrading is enabled only in RUNNING.\n\nTrading is disabled automatically when:\n- WebSocket connectivity is degraded;\n- reconciliation drift is detected;\n- recovery is active;\n- recovery fails;\n- runtime is stopped.\n\n## 4. Heartbeat\nEach accepted heartbeat records:\n- count;\n- latest timestamp.\n\nThe production watchdog should later compare the latest heartbeat against a configured freshness budget.\n\n## 5. Reconnect\nA WebSocket disconnect moves RUNNING → DEGRADED.\nA reconnect moves DEGRADED → RECOVERING.\nThe runtime must not immediately resume trading merely because the socket reconnects.\n\nRecovery must complete first.\n\n## 6. Metrics\nCurrent runtime metrics include:\n- heartbeat_count;\n- reconnect_count;\n- recovery_count;\n- order_count;\n- fill_count;\n- drift_count;\n- last_heartbeat_ms.\n\nThese counters establish the first observability contract for Testnet soak testing.\n\n## 7. Failure Injection\nThe harness is intentionally compatible with deterministic failure injection.\nRecommended scenarios:\n- disconnect during idle;\n- disconnect immediately after order submission;\n- disconnect before order acknowledgement;\n- duplicate fill delivery;\n- reconciliation drift;\n- failed replay verification;\n- recovery timeout.\n\nEvery scenario must verify that unsafe execution is blocked.\n\n## 8. Testnet Soak Test\nBefore any Mainnet consideration, the runtime should complete an extended Testnet soak run with recorded:\n- runtime uptime;\n- reconnect events;\n- recovery events;\n- order lifecycle results;\n- fill count;\n- reconciliation drift count;\n- halted states;\n- replay verification results.\n\n## 9. Acceptance Criteria\nv4.5.9 is accepted when:\n1. runtime starts deterministically;\n2. heartbeat is observable;\n3. disconnect disables trading;\n4. reconnect enters recovery rather than immediate trading;\n5. successful recovery restores trading;\n6. failed recovery leaves trading disabled;\n7. drift automatically disables trading;\n8. runtime metrics can be persisted by the surrounding observability layer.\n\n## 10. Next Step\nv4.5.10 should add production-grade watchdogs, reconnect backoff, runtime event emission and Testnet soak-test reporting.\n\n## 11. Production Boundary\nv4.5.9 remains Testnet-only and is a runtime reliability harness, not a Mainnet authorization layer.
