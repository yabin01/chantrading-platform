# v4.10.1 — Live 1M Testnet Canary

## Purpose

This release connects the read-only Hyperliquid Testnet 1M candle stream to the deterministic Live1M ChanLun structural engine.

Pipeline:

Candle WebSocket → LiveCandle → Live1MCanary → Fractal → Bi → Strict Segment → Strict Center

## Safety boundary

The canary has no order submission, execution, position, or wallet interface. It is market-data and structural-analysis only.

## Runtime invariants

- only 1m candles are accepted;
- candle timestamps must be strictly increasing at the canary boundary;
- duplicate or out-of-order candles are rejected;
- the underlying stream still ignores duplicate timestamps;
- structural state remains observable through snapshot IDs;
- no timeframe upgrade is introduced.

## Manual canary

From the repository root:

```bash
PYTHONPATH=src python scripts/run_testnet_canary.py --coin ETH --duration-seconds 600
```

The command reports received candles and the latest structural IDs.

A successful transport run is not equivalent to a trading certification. The canary must first demonstrate stable connectivity and deterministic structural processing before any execution layer is enabled.

## Next gate

The next engineering gate is a controlled soak integration:

1. record every accepted candle and structural event;
2. persist the event sequence;
3. replay the same sequence offline;
4. compare structural snapshots/events;
5. verify reconnect behavior does not duplicate structural state;
6. keep execution disabled.

Only after this gate passes should the project consider Testnet execution integration.
