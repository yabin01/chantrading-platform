# v4.11.0 — Live 1M Deterministic Soak & Replay

## Objective
Make the Live 1M structural pipeline reproducible from an ordered candle recording.

Canonical boundary:

Hyperliquid Testnet 1M candle -> SQLite append-only recording -> Live1MStructureEngine -> structural events -> snapshot/hash.

## Persistence contract
Accepted 1M candles are persisted as immutable runtime events. Event IDs are deterministic per coin/timestamp, so duplicate delivery is idempotent. The store preserves append order and payloads as canonical JSON.

The persisted candle stream is an input recording; structural replay remains read-only.

## Determinism contract
For an identical ordered candle sequence:
- emitted event sequence is identical;
- final structural snapshot is identical;
- canonical event hash is identical.

Replay must not submit orders, access wallets, or mutate the recording.

## Soak certification gate
A future soak runner must record accepted candles, structural events, reconnect lifecycle, duplicate/out-of-order rejects, final snapshot, and replay hash.

Certification requires offline replay of the recorded candle sequence and equality of the live-run structural event hash and snapshot.

## Safety boundary
v4.11.0 remains strictly read-only. This layer is evidence/replay infrastructure, not an execution engine.


## Live runtime evidence bridge

Live1MRecordedRuntime wraps the existing read-only Live1MStructureEngine. For each accepted 1M candle it appends the canonical candle event, then appends every structural event emitted by the engine.

The verification path extracts the recorded candle stream, replays it through a fresh engine, and compares:
- live structural event hash vs replay structural event hash;
- live final snapshot vs replay final snapshot.

A certification result is valid only when both comparisons match. This follows the event-sourcing principle that an ordered append-only event history can reconstruct state by replay, while idempotency and replay behavior should be tested explicitly.

## Execution boundary

This recorder does not submit orders, sign transactions, mutate positions, or make trading decisions. It is evidence infrastructure for the 1M structural pipeline.


## Recovery contract

The live recorder enforces a strict contiguous 1M candle stream before invoking the structural engine:

- identical duplicate timestamp + payload: `DROP_DUPLICATE`;
- conflicting duplicate timestamp: `RESYNC`;
- older timestamp: `RESYNC`;
- timestamp gap: `RESYNC`;
- interval other than `1m`: rejected;
- disconnect: enters `resync_required`;
- reconnect: increments a connection generation, but does not bypass the continuity gate.

Only an accepted contiguous candle reaches `Live1MStructureEngine`. Recovery events are evidence-only and are excluded from the structural replay hash. This prevents transport anomalies from becoming false ChanLun state changes.

A reconnecting consumer must therefore prove continuity before normal live processing resumes. Sequence/cursor-based replay and an explicit gap signal are common patterns for reliable realtime recovery; silently skipping an unrecoverable gap is specifically avoided.
