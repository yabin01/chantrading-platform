# v4.8.0 — Live 1M ChanLun Integration Specification

## 1. Scope

v4.8.0 connects the existing Hyperliquid Testnet 1M candle stream to the
implemented deterministic ChanLun structural engines.

Current implemented path:

```
Hyperliquid Testnet WebSocket
        ↓
LiveCandle
        ↓
Candle
        ↓
InclusionProcessor
        ↓
FractalEngine
        ↓
Strict BiEngine v4.7.1
```

This release is **read-only**. It does not submit orders and does not claim
that the full A0→An / divergence / Decision Engine is live.

## 2. Non-goals

v4.8.0 does not:
- place Testnet or Mainnet orders;
- infer 5m/15m/1h structure;
- introduce 1/2/3 buy/sell terminology;
- implement SegmentEngine, CenterEngine, or DecisionEngine;
- treat an unconfirmed fractal as a Bi endpoint.

## 3. Candle contract

Only Hyperliquid `candle` messages with `i == "1m"` are accepted.

The adapter ignores subscription acknowledgements and unrelated channels.
Duplicate candle timestamps are ignored by the canary transport.

A normalized LiveCandle is converted to the domain Candle using numeric
values without changing the source timestamp.

## 4. Structural event flow

For each accepted 1M candle:

1. InclusionProcessor updates the processed-candle sequence.
2. FractalEngine evaluates the latest three processed candles.
3. Only `FRACTAL_CONFIRMED` events are passed to Strict BiEngine.
4. Fractal invalidation is retained as an upstream event and is not silently
   converted into a new Bi.
5. BiEngine emits deterministic events such as:
   - `BI_ANCHOR_SET`
   - `BI_CONFIRMED`
   - `BI_ENDPOINT_REVISED`
   - `FRACTAL_SUPERSEDED`
   - structural rejection events.

## 5. Runtime state

`Live1MStructureEngine` maintains:
- candle_count
- latest candle
- latest confirmed fractal
- latest confirmed Bi
- emitted event history

The event history is in-process diagnostic state only. Persistent replay
remains the responsibility of the existing runtime/state infrastructure.

## 6. Determinism requirements

For identical ordered 1M candle input, the engine must produce identical
structural event types, IDs, center indices and Bi endpoints.

No wall-clock time is used by the structural engine.

## 7. Testnet safety boundary

The v4.8.0 integration is market-data only. Any future order submission must
pass through the existing Testnet execution/certification boundary and must
be implemented as a separate release.

## 8. Exit criteria

v4.8.0 is complete when:
- the live adapter can feed the existing FractalEngine;
- confirmed fractals reach Strict BiEngine;
- duplicate timestamps do not duplicate structural events;
- malformed/non-1M messages are rejected or ignored according to adapter rules;
- deterministic replay of the same candle sequence yields the same event IDs;
- the full unit suite passes.

## 9. Next stage

The next implementation stage should add the missing structural layers in
order:

```
Strict Bi
   ↓
Segment
   ↓
1M Center
   ↓
A0→An
   ↓
盘整背驰
   ↓
completed 1M fractal trigger
   ↓
HOLD / LONG / SHORT
```

Those layers must be implemented and source-validated before the runtime is
allowed to emit executable trading decisions.
