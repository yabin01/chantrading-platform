# v4.8.1 — Strict Segment Engine

## Status
Implementation stage. Scope is 1M same-level structure only.

## Source alignment
The repository's historical v1.2 specification derives the segment algorithm from
ChanLun lessons 62, 65, 67, 71 and 78. The key constraint is that "at least three
Bi" is a necessary structural basis, not the segment confirmation algorithm.
Lesson 67 introduces the FeatureSequence; the segment direction is opposite the
FeatureSequence element direction, and the standardized FeatureSequence is used
for feature-fractal detection. citeturn0search4turn0search9

## Rules frozen for this release

1. Segment direction is the direction of its first Bi.
2. FeatureSequence uses the opposite-direction Bis.
3. FeatureElements are normalized independently from candle inclusion processing.
4. Standard FeatureSequence performs direction-sensitive non-inclusion merging.
5. UP Segment searches Feature Top; DOWN Segment searches Feature Bottom.
6. Adjacent feature elements with no overlap have a gap.
7. TYPE_1: target FeatureFractal + no gap between its first/second feature elements -> SegmentConfirmed.
8. TYPE_2: target FeatureFractal + gap -> TYPE_2_PENDING; the original segment remains active.
9. TYPE_2 is not confirmed by the gap alone. The reverse FeatureSequence must later provide the required opposite FeatureFractal.
10. No MACD, EMA, higher timeframe, buy/sell points, or execution logic is allowed in SegmentEngine.

## Important implementation boundary
The current implementation provides the deterministic FeatureSequence and TYPE_1 path,
and explicitly models TYPE_2_PENDING. Reverse-feature confirmation is kept as a
separate follow-up implementation because it depends on the full candidate-segment
handoff semantics; it must not be faked by treating a gap as confirmation.

## State machine
EXTENDING -> TYPE_2_PENDING -> CONFIRMED
EXTENDING -> CONFIRMED

## Determinism
Duplicate Bi IDs are ignored. Chronological violations raise. No wall-clock time
is consulted by the structural engine.

## Traceability
Segment -> FeatureSequence -> FeatureElement -> Bi -> Fractal remains the required
audit chain.
