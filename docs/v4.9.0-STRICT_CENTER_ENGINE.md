# v4.9.0 — Strict 1M Center Engine

## 1. Scope

v4.9.0 consumes confirmed 1M Segments and produces the next structural object: the 1M ChanLun Center.

This version deliberately does not implement Ai / same-level decomposition, MACD divergence, buy/sell signals, 1/2/3 buy/sell terminology, or timeframe upgrades. The analysis level remains locked to 1M.

## 2. Source-derived definition

The historical specification in this repository defines the center as the overlap of at least three consecutive same-level completed structures. Lesson 18 describes the center using three consecutive lower-level completed movements and the interval ZD = max(lows), ZG = min(highs). A valid center requires ZD < ZG. Lesson 20 distinguishes extension of an existing center from formation of a new same-level center.

## 3. Engine input contract

CenterEngine.update() accepts only SegmentState.CONFIRMED. An unconfirmed Segment raises ValueError.

## 4. Center lifecycle

```text
confirmed Segment
       |
       v
collect 3 consecutive Segments
       |
       +-- common overlap? -- no --> candidate / wait
       |
      yes
       |
       v
CENTER_CONFIRMED
       |
       v
next confirmed Segment
       |
       +-- overlaps current [ZD, ZG] --> CENTER_EXTENDED
       |
       +-- does not overlap ----------> CENTER_TERMINATED
```

The center keeps an identity while it extends. extension_count increments for each accepted extension Segment.

## 5. Center interval

For the current center-supporting Segments:

ZG = min(segment.high)
ZD = max(segment.low)

The center exists while ZD < ZG.

For an extension, the incoming Segment must have a strict positive overlap with the current center interval:

max(ZD, segment.low) < min(ZG, segment.high)

A boundary-only touch is not treated as an overlap.

## 6. Center object

```python
@dataclass
class Center:
    id: str
    state: CenterState
    segment_ids: list[str]
    zg: float
    zd: float
    gg: float
    dd: float
    extension_count: int
    start_index: int | None
    end_index: int | None
    terminated_by_segment_id: str | None
```

segment_ids provide the structural audit chain.

## 7. Events

The engine emits CENTER_CANDIDATE, CENTER_CONFIRMED, CENTER_EXTENDED and CENTER_TERMINATED.

Events are deterministic and contain the resulting Center snapshot.

## 8. Expansion boundary

v4.9.0 does not reinterpret every non-overlapping Segment as an expansion. A non-overlap first terminates the current center.

Formation of a new same-level center and the higher-level/expanded interpretation require a subsequent confirmed Segment sequence. That logic is reserved for the next structural layer so CenterEngine does not silently change the meaning of Ai.

## 9. Determinism

The engine rejects duplicate Segment IDs, requires chronological Segment input, rejects unconfirmed Segments, exposes deterministic snapshot(), and never reads future Segments.

## 10. Explicit non-goals

CenterEngine must never emit BUY, SELL, HOLD, Divergence, or third-class buy/sell signals.

## 11. Next layer

After v4.9.0 is verified, the next planned layer is v4.9.x Center edge cases, followed by v5.0.x 1M Ai / Same-Level Decomposition.

The Ai layer will continue to use only the 1M structural stream and will not upgrade the operating timeframe when a 1M center expands.
